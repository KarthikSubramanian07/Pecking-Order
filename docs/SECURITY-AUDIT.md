# Security audit

**Date:** 2026-11-14 · **Scope:** the `main` branch at `ed99ced` plus the fixes on `fix/security` · **Disclosure policy:** [SECURITY.md](../SECURITY.md)

Pecking Order is a static, client-side app: React in the browser, data in IndexedDB, one small Cloudflare Pages Function for content negotiation and board URLs. There is no backend, no account and no secret to steal, so the audit asks a narrower question: can anything a user is handed (a file, a link, a pack, an API response, an agent's tool call) run script in the page, read data it should not, hang or crash the tab, corrupt saved boards, or make the browser contact somewhere it should not?

## Scope

| Area              | Files                                                                                                                                |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Untrusted parsing | `src/core/validate.ts`, `src/core/board.ts`, `src/core/ids.ts`, `src/packs/spec.ts`, `src/storage/peckFile.ts`                       |
| Image intake      | `src/images/transfer.ts`, `urls.ts`, `ingest.ts`, `process.ts`, `pipeline.ts`, `dimensions.ts`, `sources/*`, `src/packs/resolve.ts`  |
| Rendering         | every `src/ui/**` component that renders untrusted text, links, images or styles                                                     |
| Agents            | `src/agent/webmcp.ts`                                                                                                                |
| Platform          | `public/_headers`, `public/_routes.json`, `functions/_middleware.ts`, `functions/_lib/negotiate.ts`, `index.html`, the built `dist/` |
| Supply chain      | `package.json`, `package-lock.json`, `.github/workflows/*`, `.github/dependabot.yml`                                                 |

Method: line-by-line code review, unit tests for every fix, and a Playwright suite (`e2e/security.spec.ts`) that serves the built app with the real `dist/_headers` and fails on any CSP or Trusted Types violation.

## Threat model

**Assets.** The user's boards and images in IndexedDB, the integrity of the page (no foreign script), the responsiveness of the tab, and the user's privacy (which hosts learn they visited).

**Untrusted inputs.**

- Files and folders dropped or picked, including `.peck` backups someone else made.
- Clipboard pastes: files, HTML from other sites, URI lists, plain text, `data:` URLs.
- Remote images fetched by URL, and image search responses from Wikipedia, Wikimedia Commons and Openverse.
- Category pack JSON, both at build time (`packs/*/pack.json`) and as served from `/packs/*.json`.
- Tool calls from an in-page AI agent through WebMCP.
- HTTP requests to the Pages Function (paths, `Accept` headers).

**Attackers.** A person who shares a crafted `.peck` file or a link; a hostile or compromised web page the user copies from; a compromised image API or CDN; a prompt-injected agent; a malicious npm release.

**Out of scope.** An attacker who already runs script in the page or controls the user's browser profile, and Cloudflare itself.

## Findings

Severity is for this app's context: a static site with no server-side data, where the worst realistic outcome is a crashed tab or a damaged local board.

| ID    | Severity | Area             | Description                                                                                                                                                                                                                                                                                   | Status                                                                                                                                                                                                                                                                                                                                                                             |
| ----- | -------- | ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SA-01 | Medium   | `.peck` import   | The zip limits were per entry only: up to 2100 entries of 20 MB each, so a crafted file of a few tens of MB could inflate to over 40 GB and kill the tab. Every image entry was inflated whether or not the board used it.                                                                    | **Fixed.** Two-pass import: manifest and board first, then only images the validated board references. Caps of 5 MB per image, 20 MB for `board.json` and 250 MB for the whole file, checked against declared sizes before inflating (fflate never writes past a declared size).                                                                                                   |
| SA-02 | Medium   | Image processing | Every image went to `createImageBitmap` at full size. A small file can declare a huge canvas (a 50 kB PNG of 30000 × 30000 pixels decodes to 3.6 GB), crashing the worker and then the main-thread fallback. `.peck` imports also decoded every image just to read its size.                  | **Fixed.** `src/images/dimensions.ts` reads width and height from PNG, GIF, BMP, WebP (all three kinds), JPEG and AVIF/HEIC headers. Anything over 100 MP or 32767 px a side is refused before decoding. `.peck` images are sized from the header and skipped above 4096 px a side.                                                                                                |
| SA-03 | Medium   | Board parsing    | The id pattern accepted `__proto__`, `constructor`, `toString` and other `Object.prototype` names. A tier with id `__proto__` replaced the prototype of `board.placement`, leaving a tier with no own item list; other names shadowed built-ins. `opAddItems` trusted draft ids the same way. | **Fixed.** `isSafeKey` refuses every key `Object.prototype` owns, in `parseBoard` and `opAddItems`; lookups into untrusted objects use `Object.hasOwn`.                                                                                                                                                                                                                            |
| SA-04 | Low      | Pasting, CSP     | Pasted `data:image/*` URLs were decoded with `fetch()`, which the production CSP blocks (`connect-src` has no `data:`), so pasting image data failed on the live site.                                                                                                                        | **Fixed.** `decodeDataUrl` decodes base64 and percent-encoded payloads by hand, with the 15 MB cap checked before allocating. The CSP stays tight. Verified under the real headers in `e2e/security.spec.ts`.                                                                                                                                                                      |
| SA-05 | Low      | Network          | Any `http(s)` host was accepted, so a pasted or dropped link could make the browser request `localhost`, a router or a cloud metadata address. Production's `connect-src` allowlist already blocked this, but development builds and any future CSP change would not.                         | **Fixed.** `parseImageUrl` refuses loopback, private, link-local, CGNAT, multicast and reserved IPv4 and IPv6 addresses (including IPv4-mapped and NAT64 forms and the URL parser's `0x7f.1` style spellings), single-label names, `.local`/`.internal`/`.home.arpa` and similar, and links with embedded credentials.                                                             |
| SA-06 | Low      | Rendering        | Search API credits (author, licence, source link) went into items unchecked, and `sourceUrl` is rendered as an `href`. React 19 neutralises `javascript:` but not `data:` or other schemes, and strings were unbounded.                                                                       | **Fixed.** `ingestUrl` runs every credit through `parseCredit` (http(s) only, bounded strings). The item dialog renders the link only if it passes `safeHttpUrl` (a one-line change in `src/ui/dialogs/ItemDialog.tsx`).                                                                                                                                                           |
| SA-07 | Low      | WebMCP           | Tool arguments were coerced with `String()`, so objects became `"[object Object]"`, multi-megabyte strings passed straight through, an empty item name matched the first item (via `includes('')`) and moved it, and positions took any number.                                               | **Fixed.** Arguments are type-checked, trimmed and capped at 500 characters; empty queries match nothing; positions must be non-negative integers; `add_items` reports a full board. No tool deletes data, every change is one undo step, and `get_board` returns only the labels already on screen.                                                                               |
| SA-08 | Low      | Data integrity   | `MAX_ITEMS` (2000) was only enforced when parsing, so repeated drops or agent calls could grow a board past it, and the next reload silently dropped the extra items.                                                                                                                         | **Fixed.** `opAddItems` stops at `MAX_ITEMS`; the ingest toast says the board is full (a small change in `src/ui/actions.ts`).                                                                                                                                                                                                                                                     |
| SA-09 | Low      | Headers          | `style-src` allowed `'unsafe-inline'`, `worker-src` allowed `blob:` although the worker is a file, and Trusted Types were not enforced.                                                                                                                                                       | **Fixed.** `require-trusted-types-for 'script'` with a single policy (`src/security/trustedTypes.ts`) for inert HTML parsing and same-origin worker URLs. `style-src` uses the sha256 of the loading-shell `<style>`, filled in at build time by `csp.config.ts`; the build fails if `index.html` gains an executable inline script. `worker-src 'self'`, explicit `manifest-src`. |
| SA-10 | Low      | Supply chain     | `src/core/ids.ts` imported `nanoid`, which is not a dependency of this package; it only resolved because Vite's `postcss` hoists nanoid 3. An upgrade could have swapped the module that mints every id.                                                                                      | **Fixed.** Replaced by an unbiased `crypto.getRandomValues` generator with the same alphabet and length.                                                                                                                                                                                                                                                                           |
| SA-11 | Low      | `.peck` import   | The AVIF sniff accepted any ISO-BMFF file (MP4, MOV, HEIC), and a `null` manifest threw a raw `TypeError`.                                                                                                                                                                                    | **Fixed.** An AVIF brand is required; malformed manifests get the usual friendly message.                                                                                                                                                                                                                                                                                          |
| SA-12 | Low      | CI               | The audit job only failed on high severity, installs ran package install scripts (including in the deploy job), there was no static analysis, and Dependabot proposed releases the day they shipped.                                                                                          | **Fixed.** `npm ci --ignore-scripts` everywhere (no dependency has an install script), `npm audit --audit-level=low` plus `npm audit signatures`, a CodeQL workflow (`security-extended`, JavaScript/TypeScript and Actions, pinned by SHA), and a seven-day Dependabot cooldown.                                                                                                  |
| SA-13 | Info     | Privacy          | The pack resolver's Wikipedia and Commons lookups used fetch defaults instead of `credentials: 'omit'` and `referrerPolicy: 'no-referrer'` like every other request.                                                                                                                          | **Fixed.**                                                                                                                                                                                                                                                                                                                                                                         |
| SA-14 | Info     | ReDoS            | `upscaleThumb`'s pattern is quadratic on long strings with many `/thumb/` segments (about 300 ms for 28 kB). Input comes from a Wikipedia response.                                                                                                                                           | **Fixed.** Inputs over 2048 characters are returned untouched.                                                                                                                                                                                                                                                                                                                     |
| SA-15 | Info     | Headers          | `Permissions-Policy` covered five features and no `Cross-Origin-Resource-Policy` was sent.                                                                                                                                                                                                    | **Fixed.** Every powerful feature the app does not use is disabled (clipboard and Web Share stay, export needs them). `CORP: same-origin` on `/assets/*` and `/packs/*`.                                                                                                                                                                                                           |
| SA-16 | Info     | Redirects        | `fetch` follows redirects, so a public image URL could redirect to a private address.                                                                                                                                                                                                         | **Accepted.** `connect-src` applies to every redirect hop and Chromium's Private Network Access blocks public-to-private requests. `redirect: 'manual'` would break CDNs that redirect thumbnails.                                                                                                                                                                                 |
| SA-17 | Info     | DNS              | A public name can resolve to a private address (DNS rebinding); a browser cannot see resolved IPs.                                                                                                                                                                                            | **Accepted.** Same mitigations as SA-16.                                                                                                                                                                                                                                                                                                                                           |
| SA-18 | Info     | Images           | Formats without a header parser (TIFF, ICO) still go to the browser decoder unchecked, and photos over 100 MP (some 200 MP camera modes) are refused.                                                                                                                                         | **Accepted.** Browsers bound their own TIFF and ICO decoders; 100 MP keeps a decode under about 400 MB and covers every default camera mode.                                                                                                                                                                                                                                       |
| SA-19 | Info     | Build            | Production source maps are published.                                                                                                                                                                                                                                                         | **Accepted.** The code is open source and contains no secrets; maps make bug reports useful.                                                                                                                                                                                                                                                                                       |
| SA-20 | Info     | Headers          | `img-src` allows `data:`, and `Referrer-Policy` is `strict-origin-when-cross-origin` rather than `no-referrer`.                                                                                                                                                                               | **Accepted.** `data:` images cannot run script and the CSS grain texture is a `data:` SVG. Every fetch and every remote thumbnail already sends no referrer; link clicks share only the origin.                                                                                                                                                                                    |
| SA-21 | Info     | Deploy           | The deploy job runs `npx --yes wrangler@4.158.0`, outside the lockfile.                                                                                                                                                                                                                       | **Accepted.** The version is exact, the step runs after the build, and the token is scoped to Pages. Moving wrangler into `devDependencies` would add lockfile integrity at the cost of a large dev install.                                                                                                                                                                       |

### Reviewed and found sound

- **XSS.** No `dangerouslySetInnerHTML`, `innerHTML` or `insertAdjacentHTML` in app code (React's own internal uses are unreachable: no `<script>` elements or raw HTML props are rendered). All untrusted text is rendered as React text. SVG is only ever rasterised to a bitmap, never inserted or stored. Every `target="_blank"` link has `rel="noopener noreferrer"`. Tier colours must be an exact `#rgb`/`#rrggbb` before they reach a CSS custom property or the canvas. Pack accents map to palette swatches by name. The page `<title>` and meta tags are static.
- **DOMParser.** Pasted HTML and Commons metadata are parsed into detached documents that run no script and load nothing; only attributes and text are read. Under Trusted Types this is the only HTML sink in use.
- **Pack JSON.** `parsePack` keeps only well-formed items, clamps strings, accepts images only from the allowlisted HTTPS hosts and validates Commons names. Packs are also validated strictly at build time.
- **Pages Function.** No redirects, no reflected input except the 404 path inside a `text/markdown` body with `nosniff` and `default-src 'none'`. `/b/<id>` always serves the fixed `/` asset. Every negotiated response carries `Vary: Accept`, so caches cannot mix HTML and Markdown.
- **Storage.** Boards read back from IndexedDB go through `parseBoard` again. Images are content-addressed by SHA-256, and imported images are hash-verified.
- **Dependencies.** `npm audit`: 0 vulnerabilities at any severity. `npm audit signatures`: every installed package has a verified registry signature. Every lockfile entry resolves to `registry.npmjs.org` with an integrity hash. No package has an install script. All GitHub Actions are pinned to full commit SHAs that match their release tags, workflows default to `contents: read`, nothing uses `pull_request_target`, and secrets are scoped to the steps that need them.
- **Privacy.** No analytics, cookies or telemetry. Third-party requests happen only for features the privacy page lists (image search, pack images, pasted links), and they send no cookies and no referrer.

## Re-running the checks

```sh
npm ci --ignore-scripts

# Static checks and the unit suite, including every regression test from this audit
npx biome check .
npx tsc --noEmit
npx vitest run

# Build (fills the CSP style hash into dist/_headers, fails on inline scripts)
npm run build
grep Content-Security-Policy dist/_headers

# The app under the real production headers: fails on any CSP or Trusted Types violation
npx playwright test e2e/security.spec.ts

# Supply chain
npm audit --audit-level=low
npm audit signatures
npm query ':attr(scripts, [install]), :attr(scripts, [preinstall]), :attr(scripts, [postinstall])'
```

The regression tests live next to the code they protect: `src/core/validate.test.ts`, `src/core/board.test.ts`, `src/core/ids.test.ts`, `src/images/urls.test.ts`, `src/images/ingest.test.ts`, `src/images/dimensions.test.ts`, `src/storage/peckFile.test.ts`, `src/agent/webmcp.test.ts`, `src/security/trustedTypes.test.ts`, `src/packs/resolve.test.ts` and `scripts/csp.test.mjs`. CodeQL runs on every pull request and weekly.

To check the live headers after a deploy:

```sh
curl -sI https://pecking-order.pages.dev/ | grep -iE 'content-security|permissions|cross-origin|strict-transport'
```
